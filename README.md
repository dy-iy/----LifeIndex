# 三倍做多人生 · Lifefund

一个把课程安排、学习计时、课后复盘和个人成长指数连接起来的微信小程序。记录每节课的学习过程，通过 AI 整理复盘信息，再用分时走势与 K 线展示上课指数的变化。

目前主要实现上课场景；算法、家务、娱乐指数仍为预留入口。指数是应用内的学习反馈数值，不涉及真实资金或证券交易。

## 功能

- **课表管理**：先填写学期设置，再管理该学期的节次、周次和课程；当前选中的学期保存在数据库中，每个学期有固定编号。
- **AI 课表助手**：在当前学期内一次理解文字与 1—3 张截图，直接保存 JSONB 课程；支持缺项、分周安排、自然语言修改和重叠课程。
- **学习计时**：开始、暂停、继续和结束计时，由服务端保存状态与有效时长。
- **课后复盘**：按参与情况填写学习内容与专注自评，查看待复盘和已复盘记录。
- **AI 复盘处理**：当前链路为结构化总结、多空判断、规则校验与结算，支持失败重试。
- **上课指数**：结合计时状态和复盘事件生成连续行情，展示分时及日、周、月 K 线。
- **群聊基础管理**：支持建群、微信邀请及本人确认加入、成员移除、群名与头像编辑、本群昵称、退出、群主转让和解散。每群最多 10 人（含群主），每人最多同时加入 20 个有效群；所有成员可邀请，群主负责移除和群资料管理。圆形群头像与名称可打开「群聊设置」，前台每 5 秒静默刷新。综合指数为有效成员当前上课指数的平均值加上群累计共学奖励，未开启个人指数的成员按 1000 点计入。
- **群文字聊天**：聊天页签支持文字收发、历史记录分页、头像与本群昵称、时间分隔、长按复制和失败重试。消息保存在数据库，前台聊天每 3 秒拉取新消息；查看历史时显示新消息提示，切换页签保留记录和输入草稿。每条最多 2000 个字，发送与重试共用同一请求标识避免重复消息；只有当前有效成员可读写，退出、被移除或群解散后停止访问。
- **聊天复盘卡片**：群聊顶部为「聊天／指数／打卡」。用户完成复盘并生成结果后，后端自动向其当时有效加入的群聊发送课程名称、日期时段与有效计时时长卡片，无需手动发送或保持聊天页打开。点击卡片打开带发送成员头像和昵称的现有复盘结果弹窗。完成时复用个人结果并保存只读快照，自动重试去重，仅当前群成员可查看；后续个人修改不改写已发送结果，退出或解散的群跳过发送，不向之后新加入的群补发历史复盘。
- **群综合指数卡片**：群聊的「指数」页签使用可复用的圆角 `index-card` 组件，仅展示点数、涨跌点数、涨跌幅和分时、日 K、周 K、月 K 图。群初始基准固定为原群主建群当天个人指数的开盘价，按其个人指数时区确定当天；数据库保留 8 位精度，成员变动和群主转让不重置。当前点数为有效成员个人指数平均值加上群累计共学奖励。服务端按历史成员关系、真实个人行情及奖励发放时刻计算群曲线，第一根日 K 的开盘和首日涨跌基准使用固定初始值，后续交易日以实际群昨收为基准；周、月 K 聚合群日 K。所有群按北京时间划分交易日；旧群从迁移基线开始展示，缺失历史不补造。图表读取只允许有效成员，离群时清空卡片。
- **群成员状态列表**：指数图下方展示全部有效成员，每位成员使用两端圆弧的液态玻璃长条卡片，昵称放在头像下，不显示表头；依次展示空闲／上课中、计时中／未计时、当前课程名称与时段及个人指数简图。`GET /api/groups/{group_id}/members/status` 批量复用个人计时的课程与计时宽限规则、个人行情报价；上课状态按实际课程时间判断，暂停及超过截止时间的计时显示未计时。简图使用真实分时采样，读取不修改成员记录；前台每 5 秒刷新，快速切换页签复用进行中的读取请求。本功能无需数据库迁移。
- **群篝火每日打卡**：群聊「打卡」页按当前有效成员数绘制营灯，右上圆环展示当天已打卡人数占比。篝火下方的「成员打卡」卡片显示头像、本群昵称、本人标记和完成时间；本人未打卡时可点击「打卡」，其他成员显示不可点击的「未打卡」，完成后统一显示不可点击的「已打卡」。仅在成员列表的本人行提供打卡入口，按北京时间每日独立记录，重复点击不重复计数，重新进入页面保留服务器记录，前台每 5 秒同步成员进度。名单与进度来自同一接口响应，全员完成后出现极光，退群或移除的成员不参与当前统计。
- **全员满卡共学奖励**：最后一位成员完成当日打卡时，按当日群昨收的 3% 一次性增加群指数，例如昨收 1000 点奖励 30 点。每群每天仅发一次，只影响群指数，未满卡不扣分。奖励在同一打卡事务中保存，冻结达成时间、成员名单和计算依据；跨日保留，进退群、重复提交或刷新不会撤回或重复发放。群列表、报价、分时、日／周／月 K 共用奖励记录，次日昨收包含此前奖励；历史满卡不补发。
- **群打卡日历**：打卡页顶部可切换月份和日期，群创建日至北京时间今天的日期可选，其他日期置灰；今天显示圆环，所选日期显示绿色圆底，全员打卡日显示勾选标记。点击日期同步查看当天的篝火进度与成员状态，历史只读，不能补打卡。历史进度按当天结束时的成员名单计算，已获奖励的达成标记独立永久保存，当天后来增加成员也不会清除；旧群缺失完整成员历史且没有奖励记录的日期避免标记为满卡。日历与历史读取使用 `0031` 打卡记录及 `0032` 共学奖励记录。

- **账户与资料**：微信登录、会话续期、头像与昵称管理；时区仅在「我的」统一设置，默认北京时间。
- **微信转发**：右上角菜单转发打开小程序首页；点击群设置中圆形「邀请」加号直接打开微信原生转发界面，无邀请管理弹层。邀请卡片从创建起 1 小时内可供多人使用，旧卡片同样执行 1 小时上限，过期后显示「邀请已过期」。接收者登录后主动确认加入，打开卡片不会自动入群。

课表与学习历史分别保存。删除或替换课表会清理对应课程和实际课次，已结束计时、复盘、参与记录及指数流水使用独立快照继续保留。某课次仍在计时或暂停中时，其删除、修改会被阻止，结束计时后可以重试；未计时的当前课次允许立即删除或替换，并在课表及计时页刷新后生效。

## 技术与目录

前端使用微信原生小程序（JavaScript、WXML、WXSS）；后端使用 Python、FastAPI、SQLAlchemy、PostgreSQL 和 Alembic。课表助手使用 LangGraph 保存工作流状态，由后端调用火山方舟 `doubao-seed-2-1-pro-260915`；复盘使用 DeepSeek。

```text
.
├── miniprogram/
│   ├── pages/                     # 首页、课表、计时、复盘、行情、群聊与设置
│   ├── components/                # 共用组件
│   ├── services/                  # API 与客户端状态
│   └── config/backend.example.js  # 后端地址示例
├── backend/
│   ├── main.py                    # API 入口及后台线程生命周期
│   ├── worker_runtime.py          # 单进程后台任务管理
│   ├── agents/                    # 模型角色、提示词与工作流
│   ├── migrations/                # 数据库迁移
│   ├── schedule_worker.py         # 课表任务逻辑与人工 CLI
│   ├── learning_worker.py         # 复盘、维护逻辑与人工 CLI
│   ├── ecosystem.config.js        # PM2 进程配置
│   ├── deploy/                    # Nginx 与 systemd 配置示例
│   ├── .env.example              # 后端环境变量示例
│   └── requirements.lock.txt      # 固定版本依赖
└── project.config.example.json    # 微信开发者工具项目示例
```

后端只运行一个 `lifefund-backend` 进程。API 接收请求并保存任务，其 lifespan 同时启动课表、复盘评估和维护三个后台线程，处理课表识别保存、复盘评估、行情推进和过期计时收尾；线程在服务关闭时停止领取新任务并收尾。任务与恢复状态仍保存在 PostgreSQL。没有配置数据库时不启动后台线程。

## 本地运行

准备 Python 3.10 或更高版本、PostgreSQL、微信开发者工具，以及自己的微信小程序配置、火山方舟 API Key 和 DeepSeek API Key。以下命令使用 Bash。

### 1. 配置后端

在项目根目录执行；已有本地配置时直接编辑现有文件，避免覆盖。

```bash
cd backend
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
cp -n .env.example .env
```

先创建供本项目使用的 PostgreSQL 数据库和账户，再编辑 `backend/.env`：

| 变量 | 用途 |
| --- | --- |
| `DATABASE_URL` | 自己的 PostgreSQL 连接串，替换示例用户名、密码、地址和库名 |
| `WECHAT_APP_ID` | 自己的微信小程序 AppID，与前端项目配置一致 |
| `WECHAT_APP_SECRET` | 小程序 AppSecret，仅保存在后端 |
| `ARK_API_KEY` | 课表助手使用的火山方舟密钥，仅保存在后端 |
| `DEEPSEEK_API_KEY` | 复盘使用的 DeepSeek 密钥，仅保存在后端 |
| `SESSION_TTL_SECONDS` | 登录会话有效期 |
| `GROUP_MANAGEMENT_ENABLED` | 群管理写接口开关，默认 `false`；关闭后仍可读取群列表和详情 |
| `GROUP_INVITE_KEY_ID` | 固定邀请签名密钥编号，默认 `v1` |
| `GROUP_INVITE_SIGNING_KEY` | 服务器固定随机签名密钥，至少 32 字节，不随服务重启重新生成 |
| `AI_DAILY_REQUEST_LIMIT` | 复盘评估的每日次数配额 |
| `EVALUATION_DAILY_BUDGET_MICRO_CNY` | 每用户每日复盘评估预算，单位为百万分之一元 |

其他费用估算参数见 [环境变量示例](backend/.env.example)。课表助手目前没有每日次数或费用上限，真实模型调用会产生费用。

### 2. 初始化数据库

确认 `.env` 指向自己准备好的数据库后，在 `backend` 目录执行：

```bash
.venv/bin/alembic upgrade head
.venv/bin/python -m schedule_worker --setup
```

第一条命令应用业务表迁移，第二条初始化课表工作流的检查点表。服务启动不会自动替你执行这两步。

### 3. 启动服务

在 `backend` 目录运行一个进程，后台任务随 API 启动：

```bash
.venv/bin/python -m uvicorn main:app --host 127.0.0.1 --port 8003
```

只运行一个 Uvicorn 实例，不使用 `--workers`、`--reload` 或 PM2 cluster。运行时持有本机部署目录的独占锁，同一目录的第二个 API 实例会启动失败；锁在后台线程全部退出或进程终止后释放，不创建锁文件。独立 CLI 仍供人工初始化和单轮诊断使用，例如 `python -m schedule_worker --setup`、`python -m schedule_worker --once`、`python -m learning_worker --once`；正式部署不另行启动 worker 常驻进程。

本机访问 `http://127.0.0.1:8003/health` 应返回 `{"status":"ok"}`，接口文档位于 `http://127.0.0.1:8003/docs`。健康检查只确认 API 进程响应，不能代替数据库、微信登录或模型服务的功能验证。

### 4. 配置小程序

回到项目根目录执行：

```bash
cp -n project.config.example.json project.config.json
cp -n miniprogram/config/backend.example.js miniprogram/config/backend.js
```

将 `project.config.json` 的 `appid` 改为自己的小程序 AppID，将 `miniprogram/config/backend.js` 的 `BASE_URL` 改为自己的 HTTPS 后端地址。使用微信开发者工具导入项目根目录，并在小程序平台配置对应的合法域名。

在微信公众平台「开发 → 开发管理 → 开发设置 → 服务器域名」配置 `request 合法域名`。例如后端为 `https://api.example.com`，request 填 `https://api.example.com`。保存后，在微信开发者工具「详情 → 域名信息」刷新项目配置并重新编译。

真机需要能访问该后端地址；`127.0.0.1` 只适用于同一台机器上的本地调试。AppSecret、API Key、数据库密码和上传签名私钥均不得放进小程序代码。

群管理新增 `0026_study_group_management` 迁移，保留已有群 ID、成员及原加入时间。先核对库版本与群主成员关系、备份数据库，再应用迁移、配置固定邀请密钥和验证读取接口，最后将 `GROUP_MANAGEMENT_ENABLED=true` 开放写入。密钥可用 `python -c "import secrets; print(secrets.token_hex(32))"` 在本地生成，并仅保存到后端私有配置；不能放进小程序或公开仓库。

`0027_group_initial_open` 为群保存不可修改的建群日个人开盘基准。已有群优先从建群事件或第一次转让记录恢复原群主，再按历史个人开盘、行情和指数事件回填；无法恢复已启用指数的开盘时迁移中止，不能用当前点数替代。上线时先备份数据库、停止后端写入并迁移至 `0027`，确认原群、成员和事件记录保持不变后再启动新版后端。迁移不重置群版本或历史起点，存在群记录时禁止降级删除基准。

群资料、成员当前关系、邀请和历史变更分表保存；退出、移除和解散只改变关系或群状态，不删除个人学习数据。被移除者只能通过本次移除后新生成的邀请重新加入，旧卡片不会在再次入群后恢复有效；邀请人离群及群解散会撤销相关邀请。群名、头像修改使用版本检查，失败草稿保留；网络超时重试使用原请求标识，邀请签名凭证不保存到数据库回执、事件或日志。

群历史日 K 使用有容量上限的内存缓存加速；成员历史或历史行情补写变化时重新计算，当前交易日始终读取真实行情。每次读取仍校验数据库中的成员权限，缓存不授予访问权限。

如需暂停群管理，将写接口开关关闭并重启新版后端，保留能够识别成员状态的读取逻辑。群管理已有写入后，迁移会阻止降级；不要回退到忽略退出/移除状态的旧后端。真实微信转发、相册、聊天键盘及导航效果须在微信开发者工具及 iOS、Android 真机验证。

可以使用 [PM2 配置](backend/ecosystem.config.js) 管理唯一的 `lifefund-backend`。安装 PM2、完成环境配置及数据库初始化后，从项目根目录执行：

```bash
pm2 startOrRestart backend/ecosystem.config.js --only lifefund-backend --update-env
pm2 save
```

从旧多进程部署切换时，先停止并删除本项目的 `lifefund-schedule-worker`、`lifefund-learning-worker`、`lifefund-learning-maintenance`，再启动新版 `lifefund-backend` 并保存 PM2 列表；修改配置文件不会自动删除 PM2 中已有的进程。操作只针对 Lifefund，不使用 `pm2 delete all`。

[Nginx 示例](backend/deploy/nginx/lifefund-api.example.conf) 需要替换域名并配置自己的 HTTPS 证书。[systemd 示例](backend/deploy/systemd/lifefund-api.example.service) 使用通用安装路径，同样只启动一个进程并由 API 管理后台线程。PM2 与 systemd 选择一种方式；后台任务不另建服务。两种配置均预留 210 秒停止时间，供进行中的任务与线程收尾；超过宽限被强制终止的任务依靠持久化状态和租约恢复。

## GitHub 发布与敏感信息

公开仓库提供源码与示例配置。实际 `.env`、签名私钥、本地小程序配置、真实后端地址配置、部署配置、数据库备份、内部历史文档和个人截图均已加入 [.gitignore](.gitignore)。克隆后按上面的步骤生成自己的本地配置。

`.gitignore` 只影响未跟踪文件，不能清除已暂存的文件或历史提交。在具有完整 Git 元数据的本地仓库中，先检查是否仍在跟踪应忽略的文件：

```bash
git ls-files -ci --exclude-standard
```

如果有输出，可在 Bash 中将这些文件移出 Git 索引，保留磁盘上的原文件：

```bash
git ls-files -ci --exclude-standard -z | xargs -0 -r git rm --cached --
```

提交前查看 `git status --short` 和 `git diff --cached`，确认变更中不含真实凭据、个人数据或部署记录。若密钥曾经进入提交或已推送，应先吊销或轮换，并清理相关 Git 历史；只新增忽略规则或删除当前文件不能消除历史泄露。不要使用强制添加绕过忽略规则，也不要直接上传整个工作目录的压缩包。
